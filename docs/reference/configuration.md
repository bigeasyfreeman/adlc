# Configuration

ADLC-owned target configuration is limited to:

- `.adlc/PROJECT.md`: users, product intent, vocabulary, and non-goals;
- `.adlc/ENGINEERING.md`: architecture, conventions, verification, and release posture;
- `.adlc/config.json`: provider, loop, approval, privacy, and compatibility settings.

Repository `AGENTS.md`, `CLAUDE.md`, `CONTRIBUTING.md`, nested instructions, package metadata, and test commands remain target-owned. ADLC reads them with source paths, hashes, precedence, conflicts, warnings, and missing decisions; it does not silently replace them.

Installed bundle ownership lives in `.adlc/install-manifests/` for the transactional lifecycle and `.adlc/compat-manifests/` for compatibility targets. Do not hand-edit generated bytes and then expect update to overwrite them; drift intentionally blocks.

Credentials belong in provider-approved local stores or environment variables, never committed configuration. Telemetry is off by default.

`doc_honesty_section`: Exact schemas may evolve during 0.x with dated migration guidance.

`no_overclaim`: Configuration cannot grant authority beyond the current user approval and provider permissions.

`limitations`: Unknown provider-specific configuration is preserved and may require manual reconciliation.
