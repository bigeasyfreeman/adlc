# ADLC 0.9.2

ADLC 0.9.2 is the first publishable public-beta package candidate. It supersedes
the unpublished 0.9.1 candidate after PyPI rejected the `adlc` project name as
too similar to an existing project.

## What changed from 0.9.1

- The PyPI distribution is named `adlc-engineering`.
- The ADLC product name, `adlc_runtime` Python package, installed `adlc` skill,
  data paths, and `adlc-skill` command are unchanged.
- Release rehearsal, rollback, package metadata, and clean-install audit checks
  now derive the distribution name from `pyproject.toml`.
- The failed publication is retained as defect evidence; no v0.9.1 availability
  claim is made.

All Build, Fix, Review, installation, evidence, provider-scope, and
packet-replay controls described for the 0.9.1 candidate remain included.

## Evidence boundary

The recorded beta claim applies only to Codex Fix using the named provider,
model, harness, source commit, fixture, and evidence bundle in the provider
support matrix. Other providers and loops are not upgraded by this release.
Candidate preparation does not prove registry availability, future model
behavior, or successful external deployment.

## Publication boundary

These notes become public release notes only when the immutable `v0.9.2` tag,
the exact packet SHA-256, a schema-valid human `release_publication` approval,
and all protected GitHub environments have passed. The publishing workflow must
reuse the candidate artifact from the approved preparation-only workflow run.

## Install and rollback

Install the exact published `adlc-engineering==0.9.2` distribution only after
its artifact digest matches the approved release packet. PyPI artifacts are
immutable; a defect is corrected with a new version. Because no prior ADLC
distribution was published, rollback rehearsal restores the candidate from
immutable local test-index bytes and records that no prior public version exists.
